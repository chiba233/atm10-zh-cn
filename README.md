All the Mods 10 的简体中文汉化补丁，**同时支持 7.0 / 7.1 / 7.2 / 7.3 / 8.0**，每个整合包版本一个专属包。
整理／补译：**星野夢華 (Hoshino Yumeka)**。改动幅度较大，独立命名、独立发布；原始参考见[致谢](#许可证与致谢)。

> **装这一个就够。** 本包是**完整的一份汉化**，不是叠加在别家之上的补充包：语言文件 18.4 万余条、
> 任务书、19 本模组手册、字节码硬编码、195 张图片艺术字全都在里面（见[汉化范围](#汉化范围)）。
> **不需要**先装 BBSMC 或任何其他汉化当前置——同时装两份反而会互相覆盖。
> 整合包装好后直接装本包即可。

## 兼容版本

一次构建产出**五个专属包**，下载时对号入座：

| 整合包版本 | NeoForge | 状态 |
|---|---|---|
| All the Mods 10 **8.0** | 21.1.247 | ✅ 作者已实机验证 |
| All the Mods 10 **7.3** | 21.1.247 | ✅ 作者已实机验证 |
| All the Mods 10 **7.2** | 21.1.241 | ✅ 作者已实机验证 |
| All the Mods 10 **7.1** | 21.1.234 | ⚠️ 已按该版逐条核验，未实机验证 |
| All the Mods 10 **7.0** | 21.1.228 | ⚠️ 同上 |

Minecraft 均为 1.21.1。

**为什么要分开发**：整合包升级会改英文原文。7.1→7.2 之间 ATM 动了 13 条任务书正文，
其中 5 条是实质改写（其余是拼写修正）。逐条对过对应模组的 jar 版本之后：

| | 7.1 的原文 | 7.2 的原文 | 模组版本 |
|---|---|---|---|
| 模拟室 | 没有模式之分 | 分训练 / 推演两种模式 | **6.4.1 → 6.5.0，真升级** |
| 灌注塔 | 无视距离，走到哪都生效 | 只在设定的区块范围内生效 | 5.4.2 → 5.4.2，**同一个 jar** |
| 御腐 | 挖矿或怪物掉落 | 9 破片合 1 片簇，再用凝注台合成 | 0.9.6 → 0.9.6，**同一个 jar** |
| AE2 陨石 | 地表或地下都有 | 埋在地下、通常靠近地表 | 19.2.17 → 19.2.17，**同一个 jar** |
| 腐化怪 | 泛指「腐化怪物」 | 点名四种怪物 | 0.9.6 → 0.9.6，**同一个 jar** |

**只有模拟室那条是机制真的变了**（HNN 6.5.0 新增两种模拟模式）。其余四条模组一行代码
没动，是 ATM 把原先写得含糊或干脆写错的描述改准了——比如灌注塔，Pylons 自己的
物品提示与 JEI 说明一直写着「任意距离」，配置里也**没有**给灌注塔的范围选项
（有区块半径的是驱逐塔）；御腐那条「9 破片合 1 片簇 + 凝注台」的配方，0.9.6 的 jar
里本来就带着。

不管是哪一种，**同一句话在两个版本里的原文不同**，拿一份译文通吃就会让 7.1 玩家读到
一段通顺却对不上自己那版的中文——比漏翻危险，因为看不出来。所以按版本分叉。
**请下载与你整合包版本对应的那个包。**

各版的覆盖率（VaultPatcher 硬编码文本按**该版真实字节码**逐条核验）：

| 整合包版本 | 硬编码文本命中 | 目标类找不到 |
|---|---|---|
| 8.0 | 1382 / 1387（99.6%）| 0 |
| 7.3 | 1374 / 1377（99.8%）| 0 |
| 7.2 | 1376 / 1377（99.9%）| 0 |
| 7.1 | 1375 / 1377（99.9%）| 0 |
| 7.0 | 1351 / 1377（98.1%）| 4 |

对不上的那些是因为相关模组在老版本里是别的版本、目标类或那句话不存在，
补丁对那一版本来就不适用；数据库如实记下，不会假装生效。7.0 缺的那 4 个类
是 RFTools 建造器的三个界面与 Herbs & Harvest 的手册界面——它们在 7.0 带的
模组版本里还不存在。

这两列的算法（拿 `versions/db/<版本>/vaultpatcher.json` 就能复算）：

- **硬编码文本命中** = 在该版字节码常量池里找得到的键（精确 + 子串）÷ 需要静态核验的键总数。
  **动态替换的键不计入**（每版四千多条）：它们是运行时按表替换，静态核不了，
  算进来只会把分母灌水成一个好看的百分比。
- **目标类找不到** 不含 NeoForge 自身的 3 个类
  （`ModListScreen` 等）——扫描器只索引 `mods/*.jar`，加载器本体天然不在其中，
  五个版本里恒定如此，那是扫描范围的事实，不是补丁失效。

## 汉化范围

整合包内有 **233 个模组自带官方中文**，本包不做重复翻译，工作集中在另外三类位置：
**语言文件无法覆盖的**（界面描述文件、字节码常量、烤进 PNG 的美术字）、
**条目量极大而长期无人处理的**（蜂、奖杯、结构名一类的长尾）、
**已有中文但存在错误的**（官方译文本身有误，或同一事物在任务书与 JEI 中名称不一致）。

| 范围 | 内容 |
|---|---|
| **RFTools / XNet 全系** | 该系模组的界面不经语言文件渲染：每个界面由一个 `.gui` 文件描述，按钮与标签的文本直接写在其中，其余固化在字节码内。本包重写 **24 个 `.gui`**——建造器 / 移动器 / 载具建造器、发电与储能全线、计数器 / 传感器 / 定时器 / 排序器 / 逻辑门 / 物品检测器 / 红石收发器、XNet 控制器 / 路由器 / 无线路由器——再以字节码文本补丁补足模式选项、错误提示与聊天反馈。**枚举协议值（`Ignored` / `Copy` / `Move` 等）一律保持英文**：它们是存档与网络协议中的实际取值，翻译将导致崩溃，CI 设有硬性检查 |
| **资源蜜蜂 467 种蜂** | 蜂名、基因、蜂笼、生产表、育种链全覆盖。已捕获的旧蜂笼需另行处理——名称在捕获瞬间写入物品 NBT，更换资源包无法改变。本包附带服务端脚本，依 NBT 中的蜂种 ID 将其改写为中文，放入背包数秒后自动完成，而**命名牌自定义的名称不作任何改动**。该译文另**单独发布**为不依赖 ATM 的通用补丁（覆盖 20 个 MC 版本），与本包同源 |
| **模组手册 / 导览书** | **19 本、948 个条目**：气动工艺 231、RFTools 基础 103、极限反应堆 86、资源蜜蜂 81、工业先锋 80、模块化路由器 61、欢乐时光 50、**MFFS 全本 49**、铁路 42、生灵万物 41、激光 IO 40、高级外设 24、全能魔金 19 等，另含 **Oracle Index 神谕目录自身的界面**。手册是流程受阻最集中的位置 |
| 字节码硬编码文本 | **159 个模块、3,018 条不同原文**，指没有翻译键、固化在 class 常量池中的界面文本。每个整合包版本均以**该版真实字节码**逐条核验命中率（见[兼容版本](#兼容版本)），未命中者如实记录，不计入有效覆盖 |
| 语言文件层 | **18.4 万余条**。其中 **409 个模组游戏内的中文完全依赖本包**（官方 jar 不带中文），另有 **142 个模组**在官方基础上补齐了缺翻的键 |
| 任务书（FTB Quests）| 官方中文 + 本包补丁 **998 条**。补齐章节缺口与标题副标题；**术语以「任务绑定的物品真名」为单一真源逐条反查对齐**——全量扫描 4,168 条带物品的任务，修正 161 条名称不一致的标题（依任务书所述名称在 JEI 中检索不到，是危害最大的一类缺陷）；统一品牌与维度名（Allthemodium→ATM、Just Dire Things→可怖之物、挖矿维度，彼岸 / 异界不混用）；结构名在结构罗盘、考古战利品与任务书三处保持一致；修正维度错误、配方错误（Insanite 与 Inanite 混用，照此操作无法合成）等**具有误导性的**硬错误；修正 3 处 `&`+中文 的非法颜色码崩溃 |
| 任务书图片艺术字 | 重绘 **195 张**将标题烤进 PNG 的图片。文字取自该章节已有的中文标题，确保图片、章节名、任务名三处写法一致；配色自原图逐行采样并设有对比度下限；含装饰的图片仅替换文字区域，该区域按连通域计算，边界一旦侵入装饰即报错终止 |
| **主菜单首页** | 重绘 **14 张**按钮图为中文：单人游戏 / 多人游戏 / 选项 / 退出 / 模组 / 语言 / 租用服务器（字号与字重按玩家反馈调大调粗）；另**新增 2 个按钮**「汉化包主页」「问题反馈」，排在按钮网格倒数第二行——最下面一行留给「选项 / 退出」，那是退出的习惯位置。整合包原有按钮除「选项 / 退出」整行下移一格外，贴图与行为一个未动 |
| 两个罗盘与结构名 | 结构罗盘 / 自然罗盘的 **799 条结构名**及其自身界面。此处未汉化时只能以英文检索，而它是整合包内使用频率最高的搜索入口之一 |
| 奖杯名 | Jonn's Trophies **2.5 万条**。奖杯名是写入 NBT 的字符串，但模组将其作为翻译键使用，因而可以翻译；四种烘焙形态全覆盖 |
| 运行时拼接的名称 | 闪光生物（**2,100 条**，其 jar 内无任何中文）、魔药大师的药水词条（**155 条**，物品 ID 硬编码于代码中，不随配置变化）、按材料实时拼接的木材 / 蜜脾 / 压缩方块名。此类名称在运行时生成，手写词条无法对齐，只能依其拼装规则生成 |
| 机制层修复 | 传送石碑维度名、神秘农业作物名等**改动会影响功能**的位置，按各模组的读取方式单独处理，并维护一份不可翻译字符串清单 |

**本包同时修正了一批上游缺陷**：部分模组自带的官方中文本身有误——例如死亡提示的占位符书写错误导致该提示格式化失败、译文张冠李戴（将「步行辅助」写作「夜视」）。这些均已修正。

以上各项均由机械校验保障：物品名与任务书的一致性、蜂名、任务书断行与块结构、`.gui` 与字节码命中率、
结构名跨表一致性、须保持英文的清单，各设一道 CI 闸，未通过即无法发布；每道闸另配反例测试，
以错误输入验证其确实会失败。清单与做法见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 我该下载哪个包？

**客户端请安装文件名含 `client` 的文件，文件名中含 `server` 的是开服的人才需要下载的。**

**例如**

```
atm10-zh_cn-client-r18-atm7.3.zip
```

**就是客户端的文件。**

[Releases](../../releases) 里有两个文件：

| 文件 | 装在哪 | 谁需要 |
|---|---|---|
| `atm10-zh_cn-client-<补丁版本>-atm<整合包版本>.zip` | **你自己电脑上的 ATM10 实例** | **所有人都要装。** 单人玩家只装这一个就够了 |
| `atm10-zh_cn-server-<补丁版本>-atm<整合包版本>.zip` | **服务器**（开服的那台机器 / 面板） | 只有**开服的人**要装。纯单人玩家不用下 |

文件名里的两个版本号含义不同：`r12` 之类是**补丁自己的版本**，`atm7.2` 才是
**你的整合包版本**。认后者下载。

客户端每次启动后首次进入世界或服务器时，会异步检查 GitHub 的最新正式汉化包版本；
若有更新，会在聊天栏显示可点击的下载链接。无网络、网络受限或 GitHub 请求失败时会静默跳过，
不会影响进游戏，也不会自动下载或改写你的文件。

### 「我玩单人，客户端和服务端是不是都要装？」

**不用，只装客户端包。**

原因：单人模式下 Minecraft 在你自己的进程里跑了一个"内置服务端"，它用的就是你客户端的中文语言。
所以那些"由服务端生成"的文本（蜂笼上的蜂名、建造机的聊天反馈、任务书正文……）在单人模式下天然是中文的。
客户端包里也已经带了修正**旧蜂笼名字**用的服务端脚本（`kubejs/server_scripts/`），单人一样会执行。

**服务端包是给"开服"用的**——只有当别人连到你的服务器上玩时，那台服务器才需要它。

⚠️ **反过来千万别做**：不要把**客户端包**丢到服务器上。里面的作物名配置是纯客户端的，
上了服务器会让所有玩家进服时刷 `error creating crop with id null`。

## 客户端安装（图文步骤）

### 第 1 步：找到你的 ATM10 实例文件夹

就是**含 `mods` 文件夹和 `options.txt` 文件的那一层**。

- **CurseForge / Prism / HMCL**：在启动器里右键实例 → 「打开文件夹」/「浏览实例文件夹」
- 常见路径长这样：`...\.minecraft\versions\All the Mods 10\`

### 第 2 步：解压，并把**整个文件夹**放进去

下载与你整合包版本对应的 `atm10-zh_cn-client-…-atm<版本>.zip` 并解压，会得到一个名叫 `atm10-zh_cn-client` 的文件夹。
**把这个文件夹整个拖进实例目录**，结果应该是：

```
All the Mods 10\          ← 实例根目录
├─ mods\
├─ options.txt
└─ atm10-zh_cn-client\    ← 刚放进来的
   ├─ 双击安装-Windows.bat
   ├─ install.sh
   └─ ...
```

> 放错地方也没关系，安装器会提示你手动输入实例路径。

#### ⚠️ 两种装法，别混着来

| 装法 | 怎么做 | 结果 |
|---|---|---|
| **A. 推荐** | 把解压出的**整个 `atm10-zh_cn-client` 文件夹**放进实例目录，再运行里面的安装器 | 安装器先备份原文件再覆盖，随时可一键回退 |
| **B. 就地解压** | 直接把压缩包**内容**解压到实例根目录，让它当场覆盖 | 汉化确实生效了，但**原文件在解压的那一刻就被盖掉了，没有任何备份** |

**用了 B 之后就不要再运行安装器了**——文件已经在位，再"安装"一次等于让它把每个文件复制到自己头上。
（v7.2-release5 起安装器会识别出这种情况、跳过复制、只补 `options.txt`；更早的版本会直接报错：
`Copy-Item : Cannot overwrite the item ... with itself`。看到这个报错不代表汉化失败——
文件其实已经装好了，只差 `options.txt` 里没启用资源包，进游戏手动启用即可。）

### 第 3 步：运行安装器

- **Windows**：双击 `双击安装-Windows.bat`
- **macOS / Linux**：在该文件夹里终端运行 `bash install.sh`

选 **[1] 应用汉化**。安装器会：

1. 把将被覆盖的原文件备份到 `backups/<时间戳>/`
2. 复制汉化文件到实例
3. 在 `options.txt` 里自动启用汉化资源包（不启用会全英文）
4. 问你要不要装可选的 **JEI 拼音搜索**（能用拼音首字母搜物品，推荐装）；
   实例里已经有这个 mod 就不问了，也不会再装一份

### 第 4 步：确认装上了

**请务必检查你已启用资源包并放置在最顶部，否则大部分汉化都将失效！！！！！！！**

进游戏 → **选项 → 资源包**，「ATM10汉化包-<你的版本>」应该在**已选**那一侧，而且要在**最顶部**；
回到主菜单，按钮应该是中文（「单人游戏」「多人游戏」……）。

<p align="center">
  <img src="img/img.png" alt="资源包要在「已选」一侧的最顶部" width="720">
</p>

忘了这一步也不至于蒙在鼓里：从 `r19` 起，进世界几秒后聊天栏会告诉你资源包没生效、
或者虽然启用了却被别的包压在下面，并说明去哪里改。一切正常时它一个字都不会说。

### 升级到新版

再运行一次安装器。有新正式版时菜单里会多一项 **[u] 一键下载并更新**：它按你这份包的
**ATM 版本**去 Release 里挑对应的客户端包（不会把 7.0 的实例升成 7.2 包），
校验 SHA-256 通过后才解包，由新版安装器备份并安装，最后把备份归并回原目录、
并把原目录里的安装器本身也换成新版。校验不过或摘要缺失一律拒绝安装。
Windows 与 macOS / Linux 走的是同一套流程（`install.ps1` / `install.sh` 各自实现，行为一致）。
命令行等价写法：`bash install.sh update`。

### 卸载 / 回退

再运行一次安装器，选 **[3] 恢复备份**，一键回到安装前的状态。

## 服务端安装

**只有开服的人需要这一步。单人玩家跳过。**

下载与服务器整合包版本对应的 `atm10-zh_cn-server-…-atm<版本>.zip`，解压后按包内 `请安装前务必看我.md` 覆盖到服务器目录，然后重启服务端。

它带的东西很少，都是**必须由服务端产出**的文本：

| 内容 | 为什么必须在服务端 |
|---|---|
| `config/ftbquests/` 任务书语言 | 任务书数据由服务端下发给所有玩家 |
| `kubejs/server_scripts/` 蜂笼迁移脚本 | 老蜂笼的名字是抓蜂时烤进 NBT 的，只能由服务端改写 |
| `mods/vaultpatcher.jar` + 服务端模块子集 | 建造机聊天反馈等服务端生成的字符串 |

装完后玩家仍需各自安装**客户端包**——服务器管不了你屏幕上的物品名。

## 常见问题

- **要先装 BBSMC 或别家的汉化当底包吗？** **不用。** 本包是完整的一份，自带所有汉化文件，
  整合包装好后直接装它就行。致谢里写的「早期参考」指的是**翻译时参考过的原始文稿**，
  不是安装前置——两者只差一个字，很容易看混。
  反过来，**同时装两份汉化是不建议的**：两边都往 `resourcepacks/`、`config/`、`kubejs/`
  写同名文件，谁盖住谁取决于安装顺序，出问题也难查。要换回别家，先跑本包安装器的还原功能。
- **我玩单人，要装服务端包吗？** 不用，见[我该下载哪个包？](#我该下载哪个包)。
- **刚装好整合包、还没进过游戏就装汉化，可以吗？** 可以，但资源包顺序要留意。
  这时实例里还没有 `options.txt`（它是游戏退出时才写的）。
  安装器会新建一份，并把汉化包放在 `options.txt` 资源包列表的**最后一位**
  （对应游戏里「已选」一侧的**最顶部**）——这一点很要紧：
  游戏首次启动会把整合包的十几个内置资源包补进列表，若汉化包不在最后，
  它会被 `mod_resources` 等包整个盖掉（实测能掉到 546 个包里的第 10 位，等于没启用）。
  某些版本尚未实测出内置包顺序，这种情况下安装器**不会伪造**列表，而是提示你
  **先启动一次游戏、退出后再运行一次安装器**——那一次会把汉化包挪到最后，必定正确。
- **实例路径有中文或空格？** 支持。安装器会自动识别；手动输入路径时带不带引号都行。
- **装完还是英文？** 进游戏检查 选项 → 资源包，「ATM10汉化包-<你的版本>」必须启用，**而且要在「已选」那一侧的最顶部**——越靠上的包优先级越高，排在别的包下面等于没启用（安装器一般已自动处理）。
- **模组都是中文，唯独原版的方块 / 物品 / 界面是英文？** 不是汉化包的问题，是**启动器没把原版的中文语言文件下全**。
  这两半的中文来自两个互不相干的地方：模组的中文在各自 jar 里，跟着 `mods/` 走；
  原版的中文是启动器按资源索引单独下载的文件，躺在 `.minecraft/assets/objects/` 下。
  客户端 jar 里**只有英文**，所以后者一缺，原版就整片回落英文，而模组纹丝不动。
  **确认**：翻 `logs/debug.log`，搜 `Failed to load translations for zh_cn from pack vanilla`。
  搜得到就是这个毛病，紧跟着的 `NoSuchFileException` 会把缺的文件路径直接印出来。
  **处理**：在启动器里对这个版本跑一次文件补全 / 修复，补完重进游戏。
  补全不生效就删掉 `.minecraft/assets/indexes/<索引号>.json` 再启动，启动器会重新校验补齐——
  索引号就是日志第一行 `--assetIndex` 后面那个数字。这只动资源缓存，不碰存档和配置。
  拿第三方更新器装的整合包最容易踩这个：更新器只管模组和配置，原版资源归启动器管，两边都以为对方下了。
- **Windows 报 `Cannot overwrite the item ... with itself`？**
  你是先把压缩包内容**直接解压覆盖**到了实例根目录，**然后又运行了一次安装脚本**。
  此时脚本所在目录就是实例目录本身，它要把 `config\xxx.json` 复制到 `config\xxx.json`——同一个文件，PowerShell 拒绝。
  **汉化其实已经装好了**（解压那步就完成了覆盖），只是资源包没在 `options.txt` 里启用。
  处理办法二选一：
  1. 进游戏 → 选项 → 资源包，手动把「ATM10汉化包-<你的版本>」拖到「已选」一侧、并确保它在最顶部（最快）；
  2. 换成 v7.2-release5 及以后的安装器，它认得这种装法，会跳过复制、只补 `options.txt`。

  另外提醒：这种装法**没有备份**，恢复功能对它无效。想要能回退，请按上面的[装法 A](#-两种装法别混着来)。
- **安装器说我的版本不是最新／是测试版？** 它装之前会查一次 GitHub 上的最新正式版。
  提示只是提醒，不会拦住安装；游戏内的汉化更新提示也使用同一开关。不想让它们联网就设环境变量 `ATM_SKIP_UPDATE_CHECK=1`。
- **启动卡好几分钟，卡完日志里冒出一串 `ConnectException`？** **不是汉化包的事**，
  多半是**你的 IPv6 是黑洞**——有 IPv6 地址，但实际连不出去。

  整合包里有一批模组在启动时去拉「赞助者 / 贡献者名单」这种纯装饰数据：
  **creeperoverhaul**（`CosmeticsApi`，最毒，它是在**资源重载线程上同步**请求，直接卡住加载）、
  **titanium**（Industrial Foregoing 的前置）、**ars_nouveau**、**placebo**（Apotheosis 的前置）、
  **actuallyadditions**、**supplementaries / moonlight**。这些域名普遍同时有 IPv6 和 IPv4 地址，
  而且 **IPv6 排在前面**。浏览器和 `curl` 有 Happy Eyeballs，几百毫秒内就回落到 IPv4，所以你
  平时完全无感；**Java 没有**——它按解析顺序一个个试，每个 IPv6 地址都等满系统默认连接超时
  （macOS 是 75 秒）。一个域名 3 个 IPv6 地址，就是三分钟起步。实测 creeperoverhaul 一家
  贡献了 145 秒。

  两条命令就能确诊（超时的是 `-6`、秒回的是 `-4`，那就是它）：

  ```bash
  curl -6 --max-time 5 -o /dev/null -w 'v6 %{time_total}s\n' https://raw.githubusercontent.com/
  ```

  实测（同一台机、同一个 JDK、同一个地址，只差一个参数）：带上启动器默认塞的
  `-Djava.net.preferIPv6Addresses=system` 是 **90 秒超时失败**，再加一条
  `-Djava.net.preferIPv4Stack=true` 就是 **584ms 成功**。让 Java 走上死路的正是那条
  「跟随系统偏好」——系统按 RFC 6724 偏好 IPv6。

  **最省事的办法是直接在网卡上关掉 IPv6**（反正它在这条网络上本来就不通），
  这样跟启动器无关，浏览器以外的一切都跟着变快：

  ```bash
  sudo networksetup -setv6off Wi-Fi     # 恢复：sudo networksetup -setv6automatic Wi-Fi
  ```

  想只改游戏的话，在启动器的 **JVM 参数**里加这一条：

  ```
  -Djava.net.preferIPv4Stack=true
  ```

  再加两条兜底，让真连不上的域名 5 秒失败而不是 75 秒（只对用老 `HttpURLConnection` 的那几个
  有效，creeperoverhaul 用的是新的 `java.net.http`，不认这两条——所以上面那条才是主药）：

  ```
  -Dsun.net.client.defaultConnectTimeout=5000 -Dsun.net.client.defaultReadTimeout=5000
  ```

  HMCL 在「游戏特定设置 → Java 虚拟机参数」里填。**改完要重启 HMCL 本身**：它把这些设置
  缓存在内存里，光改 `hmclversion.cfg` 而不重启启动器，下次启动用的还是旧参数。
- **改动不生效？** 资源包类改动 **F3+T** 重载即可；VaultPatcher 硬编码文本、主菜单按钮图需**完整重启游戏**；任务书需**重进世界 / 重连服务器**。
- **蜂笼上的蜂名是英文？** 老蜂笼里的名字是抓蜂时就烙进 NBT 的，资源包改不动它，得靠脚本改写。
  **单人**：装了客户端包就已经带上这个脚本了；**联机**：需要服主装服务端包。
  两种情况都是把蜂笼放进背包待几秒自动转正；**你用命名牌起的名字永远不会被改**。
- **7.2 的任务书说灌注塔「只在设定的区块范围内」生效，是机制改了吗？** 不是，**是上游把话说岔了**，我们照原文译。
  Pylons 在 7.0/7.1/7.2 里是同一个 jar（`pylons-1.21.1-5.4.2.jar`），模组一行没动；
  配置 `pylons-server.toml` 的 `[infusion_pylon]` 也没有范围这一项（有区块半径的是驱逐塔）。
  模组自己的 JEI 说明与物品提示写的都是「任意距离」——灌注塔靠 `infusionChunkloads`
  把自己所在的区块加载起来（**每名玩家仅限一座**）来保持工作，
  所以前提是**那座塔的区块是活的**，不是你人在不在旁边。照旧玩，老教程不受影响。
  （7.2 还给 Protection Pylon 补了任务条目，那个方块 5.4.2 里本来就有，也不是新机制。）
- **JEI 里有一行灰色的 `productivebees:xxx`？** 那是模组给所有语言玩家显示的 ID 行，不是漏翻。

## 已知限制

- **JEI 拼音搜索（jecharacters）会推高启动时的内存峰值。** 它要在整合包全部
  8.7 万条配料上再建一份拼音索引，而那一刻正是启动全程内存占用最高的时候。
  内存紧张的机器上，游戏可能在「Adding N ingredients」这一步被系统杀掉——
  表现是闪退且**不留任何崩溃日志**（没有 crash-report、没有 hs_err、
  也没有 OutOfMemoryError）。遇到这种情况先把 `mods/jecharacters-*.jar`
  挪走再试；它是可选的，不装不影响汉化。
- **Sodium「粒子效果」设置里的原版粒子名无法汉化**（Cloud / Ash / Crit…）。这是 sodium-extra 0.9.3 自身的问题——它连**自己内置的**原版粒子中文都渲染不出来（选项注册时机导致翻译键解析失败），资源包无法干预。模组自定义粒子不受影响。
- **模组配置界面（Create 的「模组配置」列表打开的那些配置页）暂不汉化。** 那些标签
  没有翻译键——是把字段名按驼峰拆开现拼的，只能走 VaultPatcher 的 `dynamic` 替换，
  而那是**全局**开销：表越大，游戏里每次画文字都跟着变慢。这批有 744 条标签，
  实测会把替换表的单次成本抬高数倍，界面文字一多就掉帧（`vr14` 掉帧就是这么来的）。
  译文已经生成好留在 `src/` 里，等一个不用付全局代价的做法。
  （那个列表会枚举所有带标准配置的模组，所以受影响的不只 Create 自己的配置页。）

  顺带一提：有玩家自己改了一版 VaultPatcher，优化了动态替换那条路径——
  [suiy-2021/VaultPatcher_jdk21](https://github.com/suiy-2021/VaultPatcher_jdk21)
  （jar 在 `build/libs/`）。**本包不随包分发它，也没有对它做过任何验证**；
  作者本人也写明「不稳定，不确保没问题」。想试的自行取用、自担风险。
- **可视性能侦测（Observable）性能分析浮层上的两行计时保持英文**
  （`Duration (scroll): 30 seconds`、`Running for another 29.3 seconds`）。这两行没有
  翻译键——`observable/client/ProfileScreen$Action` 里是 `'Duration (scroll): '` 和
  `' Running for another %.1f seconds'` 这样的字面量，句子中间还夹着实时变动的数字，
  只能靠 VaultPatcher 的**子串**替换去凑，而且绕不开 ` seconds` 这种全局到处都是的
  片段。子串替换正是 `vr14` 全场景掉帧的病根，拿全局帧率换一个按快捷键才打开的调试
  浮层上的两行字不成立。该界面里有翻译键的部分照常汉化。
- 极少数模组把英文**画进了贴图**（技术边界，语言文件无能为力）。
- **CC: Tweaked 电脑终端里的文字无法汉化。** 它不走 Minecraft 的字体，用的是自带的
  `term_font.png`——256×256 的 16×16 字形表，**总共只有 256 个字符，没有任何汉字**。
  中文送进去会按字节被映射成那 256 个图形，屏幕上是一片乱码。所以 `help` 文档、
  程序输出一律保持英文，这是终端本身的物理限制，不是漏翻。
- **建造工具里第三方建筑包的单个蓝图名仍是英文。** 建筑棒的层级是
  风格 → 分类 → 子分类 → 蓝图，前三层（40 个风格、15 个分类、子分类 319 个标签里 306 个）已汉化；
  最后一层的名字取自蓝图文件名，MineColonies 自带包能经注册的小屋方块拿到官方中文，
  stylecolonies / Byzantine 这些第三方包没有翻译键，直接显示文件名。这一层共 3375 个
  不同的词，其中只有 54 个能对上官方译名，其余是 `argo_mid_b`、`aveoneupdio`、
  `0wallbot` 这类段落代号——不打开蓝图本体判断不出指什么。按「拿不准就放弃」整层保持
  原文：半译半英比全英更破坏一致性，猜出来的错译是更严重的一类问题。
- **建造工具顶部那行 `包名/类别/文件名` 路径保持英文。** structurize 把同一个字符串
  既拿去显示、又拿去当 `Map` 的键——楼层行还会把「路径:序号」塞进一个隐藏的文本控件，
  点击时用 `getText().getString()` 读回来查表。译了它就等于把键改坏：包里 458 条真实
  路径会被改掉 277 条，轻则各等级预览空白，重则查表落空直接闪退（[#3](https://github.com/chiba233/atm10-zh-cn/issues/3)
  报的就是这个）。左边那列子分类按钮显示的是路径最后一段，那一层照常汉化。
- **「Local」分类与本地结构包的说明文字**已在显示层替换，但分类名同时是传给
  `discoverPackAtPath` 的实参（客户端与服务端各存一份），说明文字又在建包那一刻就
  写进了 `pack.json` 落盘，所以**装本包之前就已存在的本地包**读的仍是自己盘上那份旧说明。
- **导览书内容按 7.2 的模组版本生成**（Patchouli / AE2 Guide 等）。三个版本共用同一份：
  实测拿 7.1 的 jar 重跑，4350 条译文有 4347 条照样落位；7.0 少 602 个文件、
  另有 97 条对不上（那几个模组在 7.0 是更老的版本）。老版本读到的导览书可能出现
  该版本没有的条目。语言文件层不受影响。
- **7.0 / 7.1 的包未经实机验证**。它们是按各自版本的真实字节码与英文底本逐条核验
  构建的（覆盖率见[兼容版本](#兼容版本)）。遇到问题请[提 Issue](../../issues)，
  会按该版的数据库定位。
- 各模组自带的官方中文若有错漏，本包尽力修正但不保证穷尽。发现漏翻 / 错译请
  [提 Issue](../../issues)，附截图与位置。
